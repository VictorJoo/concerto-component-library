소관 구분

기획과 프론트의 소관을 판정 기준으로 정리했습니다.

갈리지 않을 때 — ① 값이 아니라 관계가 문제이면 기획(호버는 면 색과 달라야 한다 → 기획 / 얼마나 다른가 → 프론트). ② 화면 하나에만 걸리면 프론트, 여러 화면에 걸치면 기획이 규칙을 정하고 프론트가 값을 정한다. ③ 그래도 갈리지 않으면 기획이 규칙을, 프론트가 값을 정한다.

소관과 무관하게 값은 이 문서 한 곳에 모은다. 프론트가 정한 값도 알려주면 반영해 버전을 올린다 — 문서를 직접 고칠 필요는 없다. 목업의 px·hex는 근사치이므로 기준으로 삼지 않는다.

1. 표기 규칙 (Convention)

본 라이브러리가 따르는 색상 토큰 표기 규칙. 화면·컴포넌트는 아래 규칙을 전제로 색을 참조한다.

① 2계층 토큰 Primitive(원시 램프, indigo-600)는 화면에서 직접 쓰지 않고, Semantic(역할 토큰, --primary)만 참조한다.
② 표기법 hex 기본. 형식은 shadcn 관례 — CSS 변수 · :root(라이트) / .dark(다크).
③ 라이트·다크 같은 토큰명에 두 값을 둔다. 별도 이름을 만들지 않는다.
④ 네이밍 소문자·하이픈(kebab), 역할→변형 순(primary / primary-foreground).
⑤ 대비 텍스트/배경은 WCAG AA(본문 4.5:1, 큰 텍스트 3:1)로 검증하고 결과를 표기한다(4장).
⑥ 상태별 표면 분리 표면(--muted) · 호버(--hover) · 선택(--selected) · 테이블 헤더(--thead)를 한 토큰으로 쓰지 않는다. 라이트 모드에서 페이지 배경·카드·헤더·호버가 모두 밝은 회청색이라 값을 가까이 두면 구분이 사라진다. 카드(#ffffff) → 호버 → 헤더 → 선택 순으로 단계를 벌린다. 목록·드롭다운 항목도 같다 — 호버에 --selected를 쓰면 마우스를 올린 항목이 이미 선택된 것처럼 보인다.
⑥ 값 출처 로그인 배너 원본에서 픽셀 추출로 확정한다(현재값은 이미지 근사치).
⑦ 문서화 항목 토큰당 이름 / 라이트값 / 다크값 / 용도 / 대비 결과.

2. 원시 색상 (Primitive) — 브랜드 인디고/페리윙클

로그인 배너·GNB 키비주얼에서 추출한 브랜드 램프. 화면에는 직접 쓰지 않고 역할 토큰이 이 값을 참조한다.

indigo (brand)
slate (neutral · cool)

3. 역할 토큰 (Semantic) — 라이트 / 다크

화면에서 실제로 참조하는 토큰. 각 토큰은 라이트·다크 두 값을 가진다. 기능색(성공·경고·위험)은 상태 구분을 위해 브랜드 블루에서 분리한다.

주요 텍스트/배경 조합의 실제 대비비. 본문 4.5:1, 큰 텍스트 3:1 이상이면 통과.

5. shadcn 토큰 정의 (형식 참고용)

색 토큰을 shadcn CSS 변수 형식으로 정리한 시안입니다. 형식 참고용이며 확정 값과 최종 반영은 프론트에서 정합니다.

공통정책 조항을 실제 동작으로 확인하는 컴포넌트 모음. 파란 칩이 공통정책 조항 번호와 매핑된다. 색은 탭1 팔레트를 그대로 사용하며, 간격·모션 등 시각 규격은 예시입니다.

상호작용 상태 — 호버 · 선택

호버 배경은 면 색과 다른 토큰을 쓴다. 호버와 선택은 동시에 표현될 수 있어야 하며 서로 구분되어야 한다. 호버 값은 대상이 놓인 면에 따라 나뉜다 — 면과 같은 값을 쓰면 반응이 보이지 않기 때문이다.

데이터 상태별 표기

화면·영역 데이터 상태에 따라 공통 표기 기준을 적용한다. 헤더·GNB·툴바는 상태와 무관하게 유지하고 데이터 영역만 대체한다. Empty(0건)와 Error(조회 실패)를 구분하며, 권한 문제는 No Permission으로 처리한다.

공통정책 7.77.6

토스트 메시지

동기 작업의 즉시 결과는 토스트로 처리한다. 성공(3초)·실패(5초)·부분 성공(5초, 일괄 작업 한정)을 사용하며, 표시 시간 경과 시 자동 소멸하고 사용자가 수동으로 닫을 수 있다. 본인이 수행한 동기 행위는 별도 알림을 발송하지 않는다.
버튼을 눌러 토스트 확인 (우측 상단)
부분 성공은 일괄 작업에서 일부만 성공한 경우에만 사용한다(형식: {작업명} {N}건 완료, {M}건 실패). 동일 내용 연속 발생 시 최신 1건으로 갱신하며, 비동기 완료·실패는 토스트가 아니라 알림으로 통지한다.
공통정책 7.3

처리 중(로딩) 상태

동기 작업(등록/저장/삭제)은 버튼 클릭 시 완료 전까지 버튼을 비활성화하여 중복 실행을 막고, 스피너로 진행 중임을 표시한다. 버튼 라벨은 유지한다(문구 교체는 구현 재량). 비동기 작업(CDE 프로비저닝·배치)은 버튼에 대기시키지 않고 요청 접수 토스트 후 완료·실패를 알림으로 통지한다.
동기 작업 — 클릭 시 라벨 유지 + 스피너 + 비활성화
비동기(CDE 프로비저닝 등)는 여기에 해당하지 않는다 — 버튼을 붙잡지 않고 "요청했습니다" 접수 토스트 후 완료/실패를 알림으로 통지한다. 진행률 바는 진행 정도를 측정할 수 있는 작업(업로드·다운로드 등)에만 사용한다.
공통정책 4.57.5

모달 · 팝오버 (닫힘 규칙 대비)

모달은 배경 상호작용을 막고 화면 중앙에 배치하며, 외부 클릭·ESC로 닫지 않고 의도적 버튼 클릭만 허용한다. 반대로 팝오버·드롭다운·플라이아웃은 외부 클릭·ESC·트리거 재클릭으로 닫으며 배경 상호작용을 막지 않는다.
모달 3유형 — 눌러서 확인 (셋 다 외부 클릭·ESC로 안 닫힘, 버튼만)
알림=통지·확인 1버튼 / 확인=결정·취소·실행 2버튼 / 입력=폼+저장·취소. 셋 다 외부 클릭·ESC로 닫히지 않고 버튼으로만 닫힌다. 입력 모달은 저장=필수값 유효 시 활성(7.1), 취소 시 입력이 있으면 확인 알럿(7.2). 삭제 확인 문구는 7.5를 따른다.

툴팁

툴팁은 호버·포커스 시 나타나는 짧은 보조 설명이다. 한두 문장 이내(용어 풀이·아이콘 의미·축약 원문)에만 쓰고, 더보기·스크롤이 필요할 만큼 길면 팝오버·상세로 처리한다. 정의가 필요한 열의 도움말은 팝오버로 제공한다.

사이드 패널 · 섹션 접기

목록에서 대상을 바꿔가며 확인하는 상세는 사이드 패널로 제공한다. 패널 안의 섹션은 성격(식별·귀속 / 속성·스펙 / 상태·현황 / 설정 / 연관 리소스)으로 나누고 최대 6개로 한다. 모든 섹션은 기본 펼침이며 사용자가 개별로 접을 수 있다. 접힘 상태는 패널을 닫으면 초기화한다.

패널에 담는 것 — 목록 컬럼만으로 부족하지만 대상에 진입할지 판단하는 데 필요한 값. 조작은 그 자리에서 끝나는 단일 액션(승인·반려 등)이나 다른 화면으로 가는 버튼만 둔다.

패널에 담지 않는 것 — ① 항목 수가 정해지지 않은 하위 목록(스크롤이 생기면 패널의 이점이 사라진다. 건수와 이동 버튼만 둔다) ② 생성·편집 폼(좁은 폭에서 입력이 눌린다) ③ 탭(탭이 필요하면 페이지로 전환한다) ④ 진입 판단과 무관한 감사용 정보. 항목 수가 소수로 고정된 목록(멤버 등)은 스크롤이 생기지 않는 범위에서 담을 수 있다.

상세와의 관계 — 상세에 항목이 추가되어도 패널에 자동으로 반영하지 않는다. 패널 추가는 위 두 기준으로 별도 판단한다. 이 조항이 없으면 검증 과정에서 상세에 있는데 패널에 왜 없냐는 지적이 반복되어 경계가 무너진다.
